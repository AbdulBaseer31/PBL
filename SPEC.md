# Vehicle Rental System (VRS): Application Spec

Source: `VRS_updated.pdf` (Database Design Project). Everything here is derived from those slides. Anything the slides did not cover but the app cannot work without is listed in **Section 11 (Deviations)** and needs sign-off.

## 1. Scope

A database-driven rental app that manages **customers, vehicles, reservations and bills**.

Flow (slide 8): **Search vehicle → Make reservation → Rent vehicle → Generate bill.**

| Layer | Tech |
|---|---|
| Database | MySQL, 4 normalized tables (3NF) |
| Backend | Java + Spring Boot REST API, plain JDBC (`PreparedStatement`) |
| Middleware | JSON Web Token (JWT) filter |
| Frontend | HTML, CSS, JavaScript talking to the API in JSON |

## 4. Database

Schema `vrs`. Column names match the ER diagram exactly. File: `src/main/resources/schema.sql`.

```sql
CREATE TABLE IF NOT EXISTS Customer (
  CustomerID     VARCHAR(10) PRIMARY KEY,
  Name           VARCHAR(50)  NOT NULL,
  Age            INT          NOT NULL,
  Address        VARCHAR(100),
  Contact_Number VARCHAR(15)  NOT NULL UNIQUE,
  Password       VARCHAR(100) NOT NULL,           -- BCrypt hash (added, see Sec. 11)
  Role           VARCHAR(10)  NOT NULL DEFAULT 'CUSTOMER'  -- CUSTOMER or ADMIN (added)
);

CREATE TABLE IF NOT EXISTS Vehicle (
  Numberplate VARCHAR(15) PRIMARY KEY,
  Type        VARCHAR(20) NOT NULL,
  Brand       VARCHAR(30) NOT NULL,
  BasePrice   DECIMAL(8,2) NOT NULL
);

CREATE TABLE IF NOT EXISTS Reservation (
  ReservationID VARCHAR(10) PRIMARY KEY,
  ReservDate    DATE NOT NULL,
  ReservPeriod  INT  NOT NULL,                    -- days
  Numberplate   VARCHAR(15) NOT NULL,
  CustomerID    VARCHAR(10) NOT NULL,
  FOREIGN KEY (Numberplate) REFERENCES Vehicle(Numberplate),
  FOREIGN KEY (CustomerID)  REFERENCES Customer(CustomerID)
);

CREATE TABLE IF NOT EXISTS Bill (
  BillID        VARCHAR(10) PRIMARY KEY,
  BillDate      DATE NOT NULL,
  Numberplate   VARCHAR(15) NOT NULL,
  CustomerID    VARCHAR(10) NOT NULL,
  ReservationID VARCHAR(10) NOT NULL UNIQUE,      -- added, see Sec. 11
  FOREIGN KEY (Numberplate)   REFERENCES Vehicle(Numberplate),
  FOREIGN KEY (CustomerID)    REFERENCES Customer(CustomerID),
  FOREIGN KEY (ReservationID) REFERENCES Reservation(ReservationID)
);
```

Rules:
- **Total cost is never stored** (it is derived, which keeps 3NF). Compute it in SQL: `Vehicle.BasePrice * Reservation.ReservPeriod`.
- **Active reservation** = reservation whose end date is after today, where end date = `DATE_ADD(ReservDate, INTERVAL ReservPeriod DAY)`.
- IDs are generated by the app: a letter + 6 random digits (`C482910`, `R103377`, `B552019`). `IdGenerator.next(prefix)`. DAO insert retries once on duplicate.
- Currency is not specified in the slides. Treat prices as plain numbers; the UI shows `$` like slide 8.

## 6. Middleware: JWT (full construction and operation)

This is the part nobody on the team has built before, so it is defined step by step. We use **a servlet filter**, not Spring Security. A filter is plain Java: it runs before any controller, looks at the request, and either lets it through or stops it.

### 6.1 Parts

| Class | Job |
|---|---|
| `JwtUtil` | Create a token. Read and verify a token. Nothing else. |
| `JwtFilter` | Runs on every request. Decides pass or block. |
| `CurrentUser` | Tiny holder (`customerId`, `role`) that the filter attaches to the request for controllers. |
| `FilterConfig` | Registers `JwtFilter` for `/*`. |
| `AuthService` | Register, login (checks password, calls `JwtUtil` to issue a token). |
| `AuthController` | `/auth/register`, `/auth/login`. |

### 6.2 The token

- Algorithm: **HS256** (one shared secret, signs and verifies).
- Claims:
  - `sub` = CustomerID
  - `role` = `CUSTOMER` or `ADMIN`
  - `iat` = issued at
  - `exp` = issued at + `vrs.jwt.expiry-minutes`
- No refresh tokens, no token blacklist. Expired means login again. Logout = frontend deletes the token.

### 6.3 `JwtUtil`

```java
@Component
public class JwtUtil {
    private final SecretKey key;
    private final long expiryMinutes;

    public JwtUtil(@Value("${vrs.jwt.secret}") String secret,
                   @Value("${vrs.jwt.expiry-minutes}") long expiryMinutes) {
        if (secret.length() < 32) {
            throw new IllegalStateException("JWT_SECRET must be at least 32 characters");
        }
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.expiryMinutes = expiryMinutes;
    }

    public String createToken(String customerId, String role) {
        Date now = new Date();
        Date expiry = new Date(now.getTime() + expiryMinutes * 60 * 1000);
        return Jwts.builder()
                .subject(customerId)
                .claim("role", role)
                .issuedAt(now)
                .expiration(expiry)
                .signWith(key)
                .compact();
    }

    // Throws JwtException if the token is bad, tampered with, or expired.
    public Claims readToken(String token) {
        return Jwts.parser().verifyWith(key).build()
                .parseSignedClaims(token).getPayload();
    }
}
```

(Method names above are for jjwt 0.12.x. If the version differs, adapt the calls but keep the public methods `createToken` and `readToken`.)

### 6.4 `JwtFilter` operation (extends `OncePerRequestFilter`)

For each request, in this exact order:

1. **Let CORS preflight through**: if method is `OPTIONS`, continue the chain. (Only needed if the frontend is ever served from another origin; static files are served by Spring Boot itself, so normally not hit.)
2. **Skip public paths** and continue the chain. Public = anything that does not start with `/vehicles`, `/reservations`, `/bills`, plus `POST /auth/register` and `POST /auth/login`. This covers the static pages, CSS and JS.
3. Read header `Authorization`. If missing or does not start with `Bearer `, respond **401** `{"error":"Login required"}` and stop.
4. Take the text after `Bearer `. Call `jwtUtil.readToken(token)`.
   - `ExpiredJwtException` → **401** `{"error":"Session expired, please login again"}`
   - any other `JwtException` / `IllegalArgumentException` → **401** `{"error":"Invalid token"}`
5. Build `CurrentUser(sub, role)` and store it with `request.setAttribute("currentUser", user)`.
6. **Admin gate** (coarse role check, done here so controllers stay simple). If the route is admin-only and role is not `ADMIN`, respond **403** `{"error":"Admin only"}` and stop. Admin-only routes:
   - `POST /vehicles`
   - `DELETE /vehicles/*`
   - `GET /vehicles/stats`
7. Continue the chain (`chain.doFilter`).

The filter writes error JSON itself (`response.setStatus`, `setContentType("application/json")`, `getWriter().write(...)`) because exceptions thrown inside a filter never reach `ApiExceptionHandler`.

### 6.5 How controllers use it

Controllers read the user with `CurrentUser user = (CurrentUser) request.getAttribute("currentUser");`. They **never** parse tokens themselves and never trust a `customerId` sent in a body when the caller is a `CUSTOMER`.

**Ownership rule (done in the service layer):** a `CUSTOMER` can only see reservations and bills where `CustomerID` equals their own. `ADMIN` sees all. Accessing someone else's record returns **404** (not 403, so we do not leak that the record exists).

### 6.6 Login and registration

- `POST /auth/register` → validate, hash password with `BCryptPasswordEncoder`, insert with role `CUSTOMER`, return the new CustomerID. **Does not** log the user in.
- `POST /auth/login` → find customer by `Contact_Number`, `matches(password, hash)`. On any failure return **401** `{"error":"Wrong contact number or password"}` (same message for unknown user and wrong password). On success return the token.
- **Admin account:** `DataSeeder` (a `CommandLineRunner`) runs at startup. If no row with `Role='ADMIN'` exists, insert one using `vrs.admin.contact` and `vrs.admin.password` (hashed).

### 6.7 Security notes (must follow)

- Passwords: BCrypt only. Never store, log or return plain passwords or hashes.
- Never log tokens or the secret.
- Every SQL statement is a `PreparedStatement` with `?` placeholders. No string-concatenated SQL.
- The frontend keeps the token in `localStorage` (acceptable for a college project; note the XSS tradeoff in README).

## 7. REST API

All bodies are JSON. All errors look like `{"error":"message"}`. Auth column: **P** = public, **U** = any logged-in user, **A** = admin only.

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/auth/register` | P | Create customer account |
| POST | `/auth/login` | P | Get a token |
| GET | `/vehicles` | U | List/search (query: `type`, `brand`, `maxPrice`, `availableOnly`), ordered by BasePrice |
| GET | `/vehicles/stats` | A | Dashboard numbers |
| POST | `/vehicles` | A | Add vehicle |
| DELETE | `/vehicles/{numberplate}` | A | Remove vehicle |
| POST | `/reservations` | U | Make a reservation (this is "Execute Rental") |
| GET | `/reservations` | U | Own reservations (admin: all) |
| GET | `/reservations/{id}` | U | One reservation (ownership rule) |
| POST | `/bills` | U | Generate bill for a reservation |
| GET | `/bills` | U | Own bills (admin: all) |
| GET | `/bills/{id}` | U | One bill with details (ownership rule) |

### 7.1 Auth

`POST /auth/register`
```json
{ "name": "Avanish Reddy", "age": 20, "address": "Hyderabad",
  "contactNumber": "9876543210", "password": "secret123" }
```
→ `201` `{ "customerId": "C482910" }`

Validation: name not blank; age 18 to 100; contact number exactly 10 digits and not already registered (`409` if taken); password at least 6 characters.

`POST /auth/login` `{ "contactNumber": "...", "password": "..." }`
→ `200` `{ "token": "...", "customerId": "C482910", "name": "Avanish Reddy", "role": "CUSTOMER" }`

### 7.2 Vehicles

`GET /vehicles?type=SUV&maxPrice=3000&availableOnly=true` → `200`
```json
[ { "numberplate": "TS09AB1234", "type": "SUV", "brand": "Honda", "basePrice": 2500.00 } ]
```
All filters optional. `availableOnly=true` hides vehicles that have an active reservation.

`POST /vehicles` `{ "numberplate": "TS09AB1234", "type": "Sedan", "brand": "Honda", "basePrice": 2500 }` → `201` with the vehicle.
Validation: all fields present; type is one of `Sedan`, `SUV`, `Hatchback`, `Bike`, `Scooter`; basePrice > 0; duplicate numberplate → `409`.

`DELETE /vehicles/{numberplate}` → `204`. Not found → `404`. Vehicle used by any reservation or bill → `409` `{"error":"Vehicle has reservations or bills and cannot be removed"}`.

`GET /vehicles/stats` → `{ "totalVehicles": 14, "activeReservations": 5, "unreservedVehicles": 9 }`
(`unreservedVehicles` = total minus vehicles that currently have an active reservation.)

### 7.3 Reservations

`POST /reservations`
```json
{ "numberplate": "TS09AB1234", "reservDate": "2026-12-01", "reservPeriod": 5, "customerId": "C482910" }
```
- `customerId` is **only read when the caller is ADMIN** (admin books on behalf of a customer, as on slide 8). For a CUSTOMER it is ignored and the token's id is used.
- Validation: vehicle exists (`404`); date is today or later; period between 1 and 30; customer exists.
- **Overlap check:** reject with `409` `{"error":"Vehicle is already reserved for those dates"}` if any existing reservation for that numberplate overlaps. Overlap rule with `end = start + period days`: `newStart < existingEnd AND newEnd > existingStart`.
- → `201`
```json
{ "reservationId": "R103377", "numberplate": "TS09AB1234", "customerId": "C482910",
  "reservDate": "2026-12-01", "reservPeriod": 5 }
```

`GET /reservations` and `GET /reservations/{id}` return the same shape (list or single).

### 7.4 Bills

`POST /bills` `{ "reservationId": "R103377" }`
- Reservation must exist and be visible to the caller (ownership rule, else `404`).
- One bill per reservation. If it already has one, return `409`.
- Copies `Numberplate` and `CustomerID` from the reservation, sets `BillDate` = today.
- → `201` bill (shape below).

`GET /bills/{id}` and `GET /bills` return:
```json
{ "billId": "B552019", "billDate": "2026-11-11",
  "reservationId": "R103377",
  "customerId": "C482910", "customerName": "Avanish Reddy",
  "numberplate": "TS09AB1234", "brand": "Honda",
  "basePrice": 2500.00, "days": 5, "totalCost": 12500.00 }
```
Built with a JOIN across Bill, Customer, Vehicle, Reservation (matches the slide 4 query style). `totalCost = basePrice * days`, computed in SQL.

## 8. Backend code conventions (summary; full list in RULES.md)

- **Models**: plain classes with private fields, a constructor, getters. No Lombok, no records-with-magic.
- **DAO**: one class per table, constructor takes `DataSource`. Each method: get connection in try-with-resources, `PreparedStatement`, map rows by hand. Methods listed below.
- **Service**: validation and business rules. Throws `ResponseStatusException(HttpStatus.X, "message")`.
- **Controller**: thin. Reads request, gets `CurrentUser`, calls service, returns result. `ApiExceptionHandler` (`@RestControllerAdvice`) converts `ResponseStatusException` into `{"error": "..."}`.

DAO methods:

| DAO | Methods |
|---|---|
| `CustomerDao` | `insert`, `findById`, `findByContactNumber`, `countByRole` |
| `VehicleDao` | `insert`, `findByNumberplate`, `search(type, brand, maxPrice, availableOnly)`, `delete`, `countAll`, `countWithActiveReservation`, `countActiveReservations`, `isUsed(numberplate)` |
| `ReservationDao` | `insert`, `findById`, `findByCustomer`, `findAll`, `hasOverlap(numberplate, start, period)` |
| `BillDao` | `insert`, `findDetailById`, `findDetailsByCustomer`, `findAllDetails`, `existsForReservation` |

## 11. Deviations from the slides (need sign-off)

The slides' schema cannot support login, roles or billing totals as drawn. Minimal additions:

1. **`Customer.Password`** (BCrypt hash). Needed for the Login screen.
2. **`Customer.Role`** (`CUSTOMER` / `ADMIN`). Needed because slide 8 shows admin actions (Add/Remove Vehicle, stats) and the JWT carries a role.
3. **`Bill.ReservationID`** (FK, unique). Without it a bill cannot tell which reservation (and so which period) it prices.
4. Extra endpoints beyond `/vehicles /reservations /bills`: `/auth/register`, `/auth/login`, `/vehicles/stats`. Login and the dashboard need them.
5. Login identifier is `Contact_Number` (unique) because CustomerIDs are generated.
6. "JWT" is read as **JSON Web Tokens** (your note said "Java Webtokens").

Still 4 tables, still 3NF.
